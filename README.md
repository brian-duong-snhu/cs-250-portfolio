# cs-250-portfolio
Repo for CS-250 Module 7 portfolio assignment

•	How do I interpret user needs and implement them into a program? How does creating “user stories” help with this?
o	The product owner can initiate discussions with the customers or users to gather requirements for their needs. The product owner would then discuss these requirements with the Scrum team and determine if there are any obstacles or prerequisites that need to be completed before the requirements can be implemented. The team can regularly meet with the customer during the sprint to clarify the needs or requirements. User stories help with this by ensuring each requirement is accounted for and by keeping track of the work progress for each requirement, what are the aspects of each requirement, and what are the acceptance criteria for each requirement to be considered as done.

•	How do I approach developing programs? What Agile processes do I hope to incorporate into my future development work?
o	Before writing the actual code, I would create wireframes and pseudocode for the logic of the user story before writing the actual code. In the logic, I would break down what needs to be constructed for this feature to work and in what logical order do I need to build out these steps. I would write unit tests for the different functions of the user story and ensure that they are properly integrated into the larger code base before having it undergo code review. Ideally, I would follow best practices with Agile processes as closely as possible for my future development work. To start out, I would incorporate test driven development such as unit tests and code reviews, continuously fixing software defects and refactoring code in each sprint, daily Scrums and/or standups to review everyone’s progress and blockers, and sprint retrospectives for continuous improvement as a team. 

•	What does it mean to be a good team member in software development?
o	To me, a good team member possesses the following qualities:
	Be responsive to team members in a timely manner
	Be engaging when collaborative on tasks and assignments
	Clearly explain how we interpret the requirements or user stories
	Keep notes of things we learn from other team members and use these as building blocks to continually develop our skillset
	When in a dispute with another team member, be willing to listen to their thought process with an open mind. If we don’t agree with the team member, try to reach a middle ground. If this is still not possible, reach out to the Scrum master to settle the dispute
